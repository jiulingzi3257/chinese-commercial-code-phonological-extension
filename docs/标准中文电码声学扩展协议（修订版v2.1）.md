## 项目定位声明

本项目**并非凭空创建全新密码编码体系**，而是依托汉语言文字固有客观特征，对**现有标准中文电码体系**做功能性合理扩展。

所有规则锚定通用拼音声学体系、国标中文电码、汉语四声平仄三大公认范式制定，无主观随意篡改规则；以文史与语言学、声学、音韵学研究视角切入编码应用领域，属于跨学科层面的体系延伸与实用优化贡献。

## 设计初衷与误区澄清

不少观点认为四位标准中文电码形式简洁即可满足需求，该看法仅局限于基础通讯标识场景，未兼顾古籍整理实操、文史考据、人机兼容、新手使用等真实痛点：

1. **简洁不代表易用**：纯四位电码高度依赖专属编码对照表。无行业手册、无相关基础的文史新手，拿到数字编码无法反向对应汉字，脱离专用码本基本无法独立使用；且网上流传的电码本文档"错讹颇多，字符错乱者比比皆是"（雪落太行《中文标准电码本整理》，2025），需要校勘后才能可靠使用。维度单一存在先天缺陷。

2. **四位电码仅聚焦汉字形体标识**：完全缺失读音、声调、语境用法等核心语言信息，无法直观体现汉字读法。

3. **无法适配汉语言复杂用字现象**：面对古籍海量多音字、同音字、通假异读字，单一字形编码不能区分读音差异与语境释义，满足不了训诂辨析需求。

4. **学科壁垒阻碍古籍数字化落地**：汉语言文学侧重形音义考据、语境释义；计算机编码侧重格式规整、机器识别，两套体系天然存在适配鸿沟。训诂学"形音义互求"原则与 NLP 的知识生产范式正在加速融合（冯志伟、张灯柯，2024；王立军团队"AI太炎"古汉语大模型，2024），单一编码维度无法打通两边诉求，会大幅拖慢古籍数字化整体进程。

5. **原生文本格式杂乱、信息承载不结构化**：长短不一的原文文本、碎片化释义，会造成大模型输入字符量波动剧烈；单薄的四位电码信息承载力不足，解析时仍需附加大量补充文本，Token 用量难以固定管控。**注（v2.0 修正）**：本点论证重心从"算力损耗不可控"调整为"为下游 NLP 提供结构化、定长的字音标注输入"——古籍大语言模型（如 AI 太炎）的训练与微调依赖高质量、可机器解析的字音/字形标注数据（李绅、胡韧奋、王立军，2024），本协议提供的"字形×字音"复合编码正是这类结构化标注的一种可行载体。

## 三层嵌套扩展逻辑

汉字天然具备**字形、声母读音、声调平仄**三大基础语言学属性，本扩展贴合文字本身特质搭建三段嵌套结构，保留原有四位电码核心作用，补足缺失维度：

1. **中段：标准四位中文电码**——保留原有优势，作为汉字唯一形体标识码，承担因形求义的考据基础，恪守通用编码规范。

2. **前段：声母顺位编码**——依据拼音声母在字母表排序生成，补充字音分类信息，支撑因声求义的训诂逻辑。

3. **尾段：四声声调编码**——按普通话四声标注，其上位范畴为平仄二分（1、2 声属平，3、4 声属仄），可区分多音字、异读字的语境用法，并可直接服务诗词格律校验。

### 一句话理论价值

传统四位中文电码看似简洁，实则依赖专属密码本，入门门槛高，且缺乏声学特征。本扩展为其新增了声母与声调两大音韵学、声学维度，使中文电码从单纯的"字形通信编码"向"音形义融合的系统科学语言模型"转变：一方面服务古籍整理中的多音字/异读标注与训诂辨析，另一方面为 TTS 多音字消歧、古籍 OCR 后处理、诗词格律校验等场景提供结构化输入，有望改变声学 AI 中 TTS 与 AI 配音的上游数据处理范式。

## 编码规则（修订版）

### 一、编码结构

```
一个汉字（一个确定的读音） → 声母码 + 标准中文电码 + 声调码
```

| 段位  | 内容     | 位数                                           | 说明                                  |
| --- | ------ | -------------------------------------------- | ----------------------------------- |
| 前段  | 声母码    | **2 位（规范模式，01–26）**；兼容模式可用 1 位（01–09 省略前导 0） | 声母首字母在英文字母表中的位次，详见映射表               |
| 中段  | 标准中文电码 | 4 位                                          | 邮电部《标准电码本（修订本）》；生僻无码字用 0000 占位并另行登记 |
| 尾段  | 声调码    | 1 位                                          | 1=阴平，2=阳平，3=上声，4=去声，0=轻声/中性调        |

**编码长度**：

- **规范模式（推荐）**：声母码恒取 2 位（01–26），编码恒为 **7 位**（2+4+1），定长规整，机器解析零歧义。
- **兼容模式**：声母码取 1 位（仅 01–09 可省前导 0），编码为 **6 位**；解析规则见"解析算法"。
- **废止 v1.0 的"4~7 位"表述**：声母(1–2)+电码(4)+声调(1) 在结构上不可能低于 6 位，"4–5 位"系口径错误。

> **说明**：下文《观刈麦》《关雎》示例表中，声母码为 01–09 的字保留了 1 位写法（6 位编码），系沿用兼容模式的历史示例；规范草案（GB/T 1.1 形态）已统一补零为 7 位定长。两者逻辑一致、仅书写精度不同，正式机器标注请按 7 位定长。

### 二、声母映射表（默认：拼音声母首字母 × 字母表位次）

本方案按《汉语拼音方案》声母表（含 y、w 作为声母位处理），以声母的首字母在 26 个拉丁字母中的位次编码：

| 声母  | 首字母 | 位次  | 声母      | 首字母               | 位次               |
| --- | --- | --- | ------- | ----------------- | ---------------- |
| b   | b   | 02  | q       | q                 | 17               |
| p   | p   | 16  | x       | x                 | 24               |
| m   | m   | 13  | zh      | z                 | 26               |
| f   | f   | 06  | ch      | c                 | 03               |
| d   | d   | 04  | sh      | s                 | 19               |
| t   | t   | 20  | r       | r                 | 18               |
| n   | n   | 14  | z       | z                 | 26               |
| l   | l   | 12  | c       | c                 | 03               |
| g   | g   | 07  | s       | s                 | 19               |
| k   | k   | 11  | y       | y                 | 25               |
| h   | h   | 08  | w       | w                 | 23               |
| j   | j   | 10  | **零声母** | a / e / o（取拼音首字母） | **01 / 05 / 15** |

**规则要点（v2.0 新增）**：

1. **复声母取首字母**：zh→26（z）、ch→03（c）、sh→19（s）。同一字母系的清浊区别（如 zh/z 同码、ch/c 同码、sh/s 同码）由中段电码保证字形唯一，前段只承担"读音分类"功能，不要求区分。
2. **y、w 按声母位处理**：按现代汉语拼音教学通例，"一、云、五、万"等字的音节首音标 y/w，取 25/23；这是实用约定，不同于《汉语拼音方案》将其定义为隔音字母的学理表述，需在协议中注明。
3. **零声母（v2.1 修正：以首字母为准）**：无辅音声母音节按其拼音**首字母**位次编码——a→01（安、爱、奥…）、e→05（恩、额…）、o→15（欧、偶…）；i/u/ü 起头音节在拼音拼写中一律写作 y/w 开头（ya、yi、wu、yu…），已按 y=25/w=23 处理，不落入零声母。**该设计的关键性质**：零声母位次 {01, 05, 15} 与全部辅音声母位次集合**互不相交**，解码时不会出现"一位两用"歧义。**00 仅作"读音未知/无法判定"占位**（生僻未识字、脱文等）。
4. **可选替换**：声母体系可整体替换为三十六字母（中古音）、方言声母（粤语、吴语等）或注音符号，仅需更换映射表，框架不变（见"扩展方向"）。

### 三、声调码规范

1. 尾段直接记录**普通话四声**：1=阴平、2=阳平、3=上声、4=去声；**0=轻声/中性调**（了、着、的、吗等，或儿化音节的轻读）。
2. **平仄是上位范畴，不是替代码**：1、2 声属"平"，3、4 声属"仄"。四声码保留全部调类信息（用于多音字区分、TTS 合成），平仄二分信息由四声码派生（用于格律校验），不单独增设码位。
3. 变调（如"一"在去声前读阳平）按**本字调**标注还是按**语流变调**标注，由使用场景决定：语料标注建议记本字调，朗读/合成场景可记变调；同一文本内须统一口径并注明。
4. **中古调类扩展**：如需处理《广韵》系统，可将尾段扩展为"平、上、去、入 + 清浊"组合编码，或按粤语九声另立映射表（见"扩展方向"），不改变前中两段结构。

### 四、多音字处理规范（字音位注册制）

本协议编码标识的是**"字位 × 字音"复合单位**（简称"字音位"）：同一汉字，读音不同、编码不同；同一读音的同一汉字，编码唯一。字形唯一性由中段电码保证，读音区分由前尾两段承担。

**多音字注册表流程**（建议作为协议附件维护）：

1. 为每个多音字建立条目：`汉字 | 标准电码 | 读音集合（拼音+四声）| 语境特征（词例/语义域/文读白读层）| 编码列表`。
2. 标注读音时须注明依据（现代辞书读音 / 古注反切 / 校本异文），同一字在不同校本中读音不同属正常，按所选底本登记。
3. 编码冲突检查：若二字同电码、同声母码、同声调码（如异体字），仍为同一"字音位"，可接受；若需进一步区分，启用扩展位（见"扩展方向"）。

**示例（"食"）**：声母 s→19，电码 7380。破读分流以"是否带宾语"为主要句法判据：

| 读音      | 句法位置与语境                          | 声调码 | 编码      |
| ------- | --------------------------- | --- | ------- |
| shí（二声） | 名词（饭食）或不及物动词，**不带宾语**：一箪食、箪食壶浆、食不饱力不足 | 2   | 1973802 |
| sì（四声）  | 及物使动动词（喂养），**带宾语**：食马者、食之不能尽其材 | 4   | 1973804 |
| yì（四声）  | 人名"郦食其"（专名异读，不适用句法判据） | 4   | 2573804 |

> 此句法判据即规范草案 9.2 节"破读句法判据"在协议原文中的具体应用；专名异读（人名、地名）另行登记，不与句法判据混用。

## 解析算法（编码 → 字音）

**正向编码**（字+音 → 码）：查声母映射表 → 查标准电码本 → 定声调码 → 依序拼接。

**反向解码**（码 → 字+音）：

```
输入：数字串 N
1. 判断长度：|N|=7  → 声母码=S[0:2]，电码=C[2:6]，声调码=T[6]（规范模式）
             |N|=6  → 声母码=S[0:1]，电码=C[1:5]，声调码=T[5]（兼容模式）
2. 声母码 S → 查映射表得声母（零声母按首字母位次 01/05/15；00 为未知占位）
3. 电码 C → 查标准电码本得汉字（如 C=0000，标记"未登记生僻字"）
4. 声调码 T → 1/2/3/4/0 对应四声与轻声
5. 输出：汉字（电码）+ 声母 + 声调 = 字音位
```

**歧义说明**：兼容模式下 6 位编码的声母码仅可为 01–09（1–9），不会与 10–26 冲突，故 6/7 位判断无歧义。规范模式推荐全程 7 位，机器解析零歧义。

## 韵母码（扩展层，v2.1 新增）

在声母码、声调码之外，将**韵母**纳入编码体系，构成"全息编码"，为加密层提供完整字音输入。

### 全息编码（9 位）

```
汉字 → 声母码(2) + 韵母码(2) + 标准电码(4) + 声调码(1) = 9 位
```

中段 4 位电码始终是"字形锚"；前 4 位（声母+韵母）拼出完整字音；尾位声调提供调类。9 位全息码可做到"同字异音异码、同音异字异码"的完全区分。

> **两种全息码方案并存说明**：本协议原文采用 **9 位方案**（韵母 2 位线性码，便于手工速查与加密演示）；规范草案（GB/T 1.1 形态，见 `docs/标准中文电码声学音韵学扩展编码规范_草案.md` 第 7 章）另列 **10 位方案**（韵母结构码 3 位 = 韵头 + 韵腹 + 韵尾，记录音位层四呼与韵尾结构）。两者框架一致（声母—电码—韵母—声调），仅韵母段位数与抽象层级不同：9 位用于协议演示、手工加密与快速查阅，10 位用于机器标注、学术正式规范与跨方言扩展，可按场景选用。

**拼写韵母原则**：按拼音字符串中声母之后的字母串取韵母（zhī→i、diǎn→ian、jūn→ün、xiào→iao、guān→uan、lǐng→ing），便于 TTS/OCR 机器直接解析；ê 与 -i(前/后) 在拼写层并入 e/i，不另设码。

> **v2.1 修订注（韵母的性质）**：《汉语拼音方案》的韵母系统在编码学上有三个本质特性：①**组合系统**——39 个韵母由"韵头(介音)×韵腹(元音)×韵尾"生成，不是离散清单，线性编号与语音现实脱节；②**拼写省略（压缩）**——iou→iu、uei→ui、uen→un、ü 省两点，拼写层与音位层非双射，同一拼写在音位层需先"展开"；③**上下文相关（音位变体）**——a 在 an/ang/ian 中读 [a]/[ɑ]/[ɛ]，zhi/chi/shi/ri/zi/ci/si 的"i"是空韵母（舌尖元音）。因此**韵母不宜作线性编号的主维度**，上表 35 个拼写码降级为"机器速查表"；学术正确姿势是下方结构编码，密码学正确姿势是"校验分量"与"自密钥"角色。

### 韵母结构编码（音位层，3 位）——推荐

按汉语音节的客观构造编码：`韵头(四呼) 1 位 + 韵腹(元音) 1 位 + 韵尾 1 位`：

| 韵头（四呼） | 码   | 韵腹（元音） | 码   | 韵尾  | 码   |
| ------ | --- | ------ | --- | --- | --- |
| 无（开口呼） | 0   | a      | 1   | 无   | 0   |
| i（齐齿呼） | 1   | o      | 2   | i   | 1   |
| u（合口呼） | 2   | e      | 3   | u   | 2   |
| ü（撮口呼） | 3   | i      | 4   | n   | 3   |
|        |     | u      | 5   | ng  | 4   |
|        |     | ü      | 6   |     |     |
|        |     | er / ê | 7   |     |     |

示例（**拼写层必须先展开为音位层再编码**）：ian = i+a+n → **113**；uang = u+a+ng → **214**；ün = ü+ü+n → **363**；ui（拼写）→ uei（音位）= u+e+i → **231**；iong = i+o+ng → **124**；er → **070**。

**该编码的三重红利**：①结构码直接携带"四呼"信息（韵头位），而四呼正是声韵配合的索引；②拼写省略规则被迫显式化（ui 必须展开为 uei），消除拼写层歧义；③三位分量各自是 0–3/1–7/0–4 的闭合小值域，可独立参与运算。

### 韵母在加密中的三种角色（v2.1 新增）

| 角色                    | 做法                                                                                | 密码学意义                                                                             |
| --------------------- | --------------------------------------------------------------------------------- | --------------------------------------------------------------------------------- |
| **① 校验分量**（最推荐，零编码成本） | 不编码韵母；以"声母码 × 韵头(四呼)"查声韵配合约束表（j/q/x 只配齐齿/撮口，b/p/m/f 只配开口/合口等），非法组合即判定"码有误或非普通话读音" | 普通话合法音节仅约 400 个（21×39=819 组合中近半非法），声母×韵母组合自带**合法性判定**，如同内置校验位；可直接用于古籍异读辨析与 OCR 纠错 |
| **② 自密钥**             | 模式 B 栅栏加密的密钥由**该字韵母结构码派生**（如密钥种子 = 数字根(韵头+韵腹+韵尾)），不外部给钥                           | 密钥随字而变、不随密文外泄——"一次性密钥"思想的汉字版；韵母成为加密的内部密钥源                                         |
| **③ 差分混入**            | 模式 C 步骤②差分后，d2d3 再与韵腹码（或数字根(韵母结构码)）做一次模 10 混入                                     | 让韵母参与折叠但保持可复算；实现"声母+韵母+声调"三要素全参与的手工加密                                             |

## 加密与指纹层（v2.1 新增）

### 设计纪律（先立规矩）

可复算的加密必须满足三条：

1. **函数确定**：每一步都由明确公式定义，不允许"取哪个因数""要不要对调"这类自由选择；
2. **取整法统一**：四舍五入、进一法、去尾法三选一，全文一致（原手算示例混用取整法是算错主因）；
3. **运算封闭**：结果落在固定位数（不足补 0、超位取模）。

### 模式 A：4 位单向指纹（校验 / 脱敏 / 防篡改）

输入全息码（S 声母、Y 韵母、C 电码、T 声调），输出 4 位指纹 F = d1 d2 d3 d4：

```
d1   = 数字根(S + Y)               // 声韵混合，1-9
d2d3 = (C + S×Y + T) mod 97        // 电码与声韵调混合，2 位（不足补 0）
d4   = (数字根(C) + T) mod 10      // 尾校验
```

演示（西，全息 240460071）：

- d1 = 数字根(24 + 04 = 28) = 1
- d2d3 = (6007 + 24×4 + 1) mod 97 = 6104 mod 97 = 90
- d4 = (数字根 6007 = 4 + 1) mod 10 = 5
- 指纹 = **1905**（可随时复算验证）

### 模式 B：可逆栅栏加密（传输保密，带密钥）

```
密文 = 栅栏置换(全息码) ⊕ 密钥     // ⊕ 为逐位 mod 10 相加
明文 = 逆栅栏(密文 − 密钥)          // 减法亦逐位 mod 10
```

演示（西，全息 240460071，密钥 135790246）：

- 栅栏深度 2：奇位 20601 + 偶位 4407 → 206014407
- 逐位 + 密钥 → **337046343**
- 解密：337046343 − 135790246 → 206014407 → 逆栅栏 → 240460071 ✓ 可逆还原

### 模式 C：手工折叠加密（用户原创三步法 · 定稿版 v1）

作者原述："先对声母进行因子分解，然后根据声调码对中间四位数进行差分与四舍五入小数化处理，又使用了对称栅栏。……我也不太清楚当时如何加密了！反正好像都是小学数学来加密……拆数取大法和因子分解我都会用的，取整法和四舍五入对调，都根据声调码做动态调整。"（2026-09-11）

**定稿说明**：作者确认原手算为"即兴加密"（规则动态调整、无法复现）。经七例验证，**"标准四舍五入 + 对称分段差分 + 声调置位"是被魂、西两例独立验证的干净子集**，本版以其为默认参数固化；即兴变体（进一法、对调）不再纳入定稿，如日后需要可经"即兴加密日志"另行归纳。

```
输入：S(2 位声母码)、C(4 位电码)、T(1 位声调码)
输出：4 位密文 d1 d2 d3 d4

步骤① 拆数取大 → d1（定稿规则）：
  S ≤ 9          ：d1 = S        （04→4、08→8）
  3 | S          ：d1 = S ÷ 3    （24→8、12→4、21→7、18→6、15→5）
  3 ∤ S 且 S≥10  ：d1 = (S ÷ 2) 的个位（10→5、22→1、26→3）

步骤② 声调驱动差分 → d2d3（定稿规则）：
  C' = 对 C.T 作标准四舍五入（.5 及以上进，以下舍）
  对称栅栏分段：C' = 前两位 | 后两位
  d2d3 = |前两位 − 后两位|

步骤③ 置位 → d4：d4 = T

密文 = d1 d2d3 T
```

## 扩展方向（开放框架）

本协议底层结构为开放框架，可扩展而不破坏中段电码核心：

1. **声母体系替换**：三十六字母（中古音系）、粤语/吴语等方言声母、注音符号、国际音标（声母位转写为编号），仅更换映射表。
2. **声调体系扩展**：普通话四声 → 中古四声八调（平上去入 × 清浊）、粤语九声六调、闽南语七调等，尾段按新调类重编号。
3. **可叠加层（加密/定位）**：可与三阶幻方、紫微斗数排盘等结合，在编码序列上做二次置换，形成多层加密；亦可前接 Unicode/区位码、后接词性/义项位，扩展为"汉字属性标注语言"。栅栏置换与逐位模加的具体实现见上文"加密与指纹层"（模式 B，含密钥与解密流程）。
4. **工具链配套**：建议配套开发（a）码本查询/校勘工具（现有网传码本错讹多，需以纸质《标准电码本（修订本）》1983 年第 3 版为底本校勘）；(b) 多音字注册表数据库；(c) 编码⇄汉字批量转换脚本，并公开映射表与测试集，供 TTS、OCR、NLP 团队直接取用。
